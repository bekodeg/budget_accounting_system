# 15. Месячный план по категориям

## 15.1. Область планирования

План относится к конкретному бюджету, календарному месяцу и категории расходов.

Ключ уникальности:

    (budget_id, month, category_id)

Месяц всегда нормализуется до первого дня:

    2026-09-29 -> 2026-09-01

## 15.2. Денежные значения

Плановые суммы хранятся только в minor units (BigInt / SQLite INTEGER). Вычисления через
double не используются.

Отрицательная плановая сумма запрещена.

## 15.3. Нулевая сумма и очистка

Значение 0 означает очистку плана для выбранной категории и месяца. Строка plans
удаляется, а UI отображает для этой категории нулевой план.

Такое поведение не создает бессмысленные нулевые записи и сохраняет уникальность
(budget_id, month, category_id).

## 15.4. Архивные категории

Активные категории типов EXPENSE и BOTH доступны для редактирования плана.

Архивная категория:

- не предлагается для создания нового плана;
- остается доступной в историческом месяце, если план для нее уже существовал;
- отображается как историческая и не редактируется.

Категории INCOME не участвуют в расходном плане.

## 15.5. Реактивность

PlanReceiptDao.watchPlansForMonth возвращает Drift stream. После upsert или очистки
план выбранного месяца обновляется без ручного refresh.

## 15.6. Слои

    MonthlyPlanScreen
      -> WatchMonthlyPlan / SetMonthlyPlanAmount
      -> PlanRepository
      -> DriftPlanRepository
      -> PlanReceiptDao
      -> SQLite / Drift

Presentation не импортирует Drift-типы.

## 15.7. Схема БД

Для этой функции изменение schema v1 не требуется: таблица plans и уникальный индекс
uq_plans_budget_month_category уже были заложены в исходную схему.
