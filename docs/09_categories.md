# 9. Категории бюджета

## 9.1. Назначение

Категории принадлежат конкретному бюджету и используются для классификации доходов и расходов.

Поддерживаются три типа:

- `EXPENSE` — расход;
- `INCOME` — доход;
- `BOTH` — может использоваться для обоих типов операций.

Категория не удаляется физически после того, как могла попасть в историю. Вместо удаления используется `is_archived`.

## 9.2. Источник истины

Категории хранятся в Drift/SQLite в таблице `categories`.

Application и presentation работают с доменной моделью `BudgetCategory` через `CategoryRepository`. Drift-типы не выходят за пределы data-слоя.

Основные операции:

```text
watch categories
create category
rename category
archive category
apply standard templates
```

## 9.3. Стандартные шаблоны

Таблица `category_templates` заполняется при создании БД.

При первом onboarding пользователь видит опцию «Добавить стандартные категории». По умолчанию она включена.

Если пользователь согласился:

1. application получает список шаблонов;
2. для каждого шаблона строится детерминированный category id;
3. `User`, `Budget`, `OWNER membership` и все начальные категории записываются в одной SQLite-транзакции.

Формат id шаблонной категории:

```text
<budgetId>:template:<templateCode>
```

Например:

```text
budget-123:template:expense.food
```

Это делает повторное применение шаблонов идемпотентным.

## 9.4. Повторное применение шаблонов

В экране категорий доступно действие «Добавить стандартные».

Повторный запуск:

- добавляет только отсутствующие template IDs;
- не создает дублей;
- не перезаписывает пользовательское переименование;
- не разархивирует ранее архивированную template-категорию.

Для этого data-слой использует `insertOrIgnore`.

## 9.5. Архивирование

Архивирование изменяет только:

```text
categories.is_archived = true
```

Запись остается в БД.

Это обязательное правило, потому что существующая транзакция хранит `category_id` как внешний ключ.

После архивации:

- категория не попадает в список активных категорий;
- категория не должна предлагаться при создании новой транзакции;
- историческая транзакция продолжает ссылаться на ту же категорию;
- категория доступна через запросы с `includeArchived: true`;
- экран управления показывает ее в блоке «Архив».

Физическое удаление категории пользовательским CRUD не выполняется.

## 9.6. Сортировка

Drift возвращает категории в стабильном порядке:

```text
kind ASC
name ASC
id ASC
```

Третий ключ нужен для детерминированного порядка при одинаковых названиях.

UI дополнительно группирует активные категории в порядке:

1. расходы;
2. доходы;
3. доходы и расходы.

Архив показывается отдельным блоком.

## 9.7. Создание и переименование

Названия нормализуются в application-слое:

- пробелы по краям удаляются;
- пустое название запрещено.

Создание категории:

```text
UI
 -> CreateCategory
 -> IdGenerator
 -> CategoryRepository
 -> DriftCategoryRepository
 -> CategoryAccountDao
 -> SQLite
```

Переименование не меняет идентификатор категории, поэтому исторические ссылки сохраняются.

## 9.8. Поток чтения для будущих транзакций

Для формы новой транзакции следует использовать:

```dart
watchBudgetCategories(
  budgetId,
  includeArchived: false,
)
```

Для истории, отчетов и экранов, где нужно разрешить старый `category_id`, разрешено использовать `includeArchived: true`.

Таким образом архивная категория никогда не становится недоступной для чтения исторических данных.

## 9.9. Тестирование

Задача покрыта на нескольких уровнях:

- unit:
  - создание и нормализация имени;
  - запрет пустого имени;
  - deterministic template IDs;
  - идемпотентное применение шаблонов;
  - rename + archive;
- Drift integration:
  - чтение seeded templates;
  - стабильный порядок;
  - повторное применение шаблонов без дублей;
  - active/all category queries;
  - сохранение transaction → category после архива;
  - атомарность onboarding вместе с initial categories;
- widget:
  - создание категории;
  - переименование;
  - архивирование;
  - opt-out стандартных категорий при onboarding.

Полный Flutter/analyze/coverage/APK gate выполняется на `stage` согласно `docs/07_ci_quality_gates.md`.
