# 11. Доходы и расходы

## 11.1. Базовый сценарий

Раздел «Операции» является реактивным журналом активного бюджета.

Пользователь может:

- создать доход;
- создать расход;
- изменить дату/время, сумму, счет, категорию и комментарий;
- удалить операцию через soft delete.

Автор операции не вводится вручную. Он берется из активного локального `userId`.

## 11.2. Application flow

Создание:

```text
TransactionEditor
 -> CreateTransaction
 -> RequireAccountInBudget
 -> RequireCategoryInBudget
 -> TransactionDraft domain validation
 -> TransactionRepository
 -> TransactionDao
 -> SQLite
```

Редактирование сначала загружает существующую активную операцию по паре
`(budgetId, transactionId)`, а затем применяет те же проверки.

## 11.3. Инварианты

До записи проверяются:

- сумма строго больше нуля;
- счет существует в текущем бюджете и не архивирован;
- категория существует в текущем бюджете и не архивирована;
- EXPENSE использует категорию EXPENSE/BOTH;
- INCOME использует категорию INCOME/BOTH;
- валюта суммы совпадает с валютой счета;
- автор берется из активной сессии.

Data-layer дополнительно проверяет принадлежность счета бюджету.

## 11.4. Деньги

UI принимает десятичную строку и преобразует ее в minor units.

В SQLite хранится только целое `amount_minor`; floating point для финансовых
вычислений не используется.

Валюта операции фиксируется в момент сохранения и совпадает с валютой счета.

## 11.5. Редактирование

При редактировании сохраняются:

- `id`;
- `budget_id`;
- исходный `author_id`;
- `created_at`.

Меняются пользовательские поля и `updated_at`.

Операция другого бюджета не может быть изменена через application/data API.

## 11.6. Удаление

Физическое удаление не выполняется.

```text
deleted_at = now
updated_at = now
```

Все обычные streams и отчеты фильтруют `deleted_at IS NULL`.

Это позволяет позднее использовать запись для аудита и синхронизации.

## 11.7. Реактивный журнал

`WatchTransactions` подписан на Drift stream активного бюджета.

Порядок:

```text
occurred_at DESC
updated_at DESC
id DESC
```

После create/update/delete UI обновляется автоматически без ручного refresh.

На задаче #12 этот stream расширяется фильтрами и отображением связанных
сущностей.

## 11.8. Тестирование

Покрыты:

- create expense и автоматический author;
- несовместимая категория;
- update с сохранением автора;
- soft delete;
- Drift create/update/watch/delete;
- сортировка новых операций;
- widget create/edit/delete;
- regression-тесты счетов и onboarding после расширения transaction API.

Полный Flutter/analyze/coverage/APK gate выполняется на `stage`.
