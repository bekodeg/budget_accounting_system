# 13. Журнал операций и фильтры

## 13.1. Журнал

Раздел «Операции» показывает только записи активного бюджета с
`deleted_at IS NULL`.

Сортировка детерминирована:

```text
occurred_at DESC
updated_at DESC
id DESC
```

Строка журнала содержит:

- сумму и валюту;
- дату/время;
- счет или направление transfer;
- категорию либо «Перевод»;
- автора;
- комментарий.

Архивные счета и категории остаются доступными справочниками для отображения
исторических записей.

## 13.2. Фильтры

`TransactionFilter` поддерживает комбинирование:

- `fromInclusive`;
- `toExclusive`;
- тип операции;
- category id;
- account id;
- author id.

Границы периода имеют семантику `[fromInclusive, toExclusive)`.

Фильтр счета для transfer проверяет оба поля:

```text
account_id = selected
OR destination_account_id = selected
```

## 13.3. Где выполняется фильтрация

Фильтрация выполняется в `TransactionDao.watchFiltered`, а не после загрузки
всей истории в widget.

Каждый заполненный параметр добавляет SQL/Drift predicate.

Это сохраняет отзывчивость журнала на растущей локальной истории и позволяет
SQLite использовать существующие индексы.

## 13.4. Реактивность

`WatchFilteredTransactions` возвращает Drift stream.

После create/update/soft delete SQLite инвалидирует запрос, и текущий список
пересчитывается автоматически. Ручной refresh не нужен.

## 13.5. Автор

S2 является однопользовательским этапом. UI предлагает фильтр «Только мои»,
который подставляет текущий `userId`.

Repository/API уже принимает произвольный `authorId`, поэтому на этапе
совместного бюджета UI можно заменить на выбор участника без изменения SQL
контракта.

## 13.6. Период

UI позволяет независимо установить начальную и конечную календарную дату.

Конечная выбранная дата преобразуется в начало следующего дня, поэтому весь
выбранный день входит в период без ручных значений 23:59:59.

## 13.7. Тестирование

Покрыты:

- комбинация period/type/category/account/author;
- исключение soft-deleted записей;
- only-my filter в widget;
- reset фильтров;
- реактивное появление новой операции при активном фильтре.

Полный Flutter gate выполняется на stage.
