# 18. Роли участников и авторизация бюджета

## 18.1. Роли

В бюджете используются три роли:

| Роль | Чтение | Экспорт | Изменение данных | Управление участниками |
| --- | --- | --- | --- | --- |
| OWNER | да | да | да | да |
| EDITOR | да | да | да | нет |
| VIEWER | да | да | нет | нет |

Под изменением данных понимаются операции, переводы, счета, категории и месячный план.

## 18.2. Где проверяются права

UI скрывает недоступные действия, но это только UX-слой.

Фактическая проверка выполняется application layer через:

    AuthorizeBudgetAction
      -> SessionStore
      -> MembershipRepository
      -> UserBudgetDao
      -> budget_members

Mutation use case обязан вызвать authorization guard до записи в repository/DAL.

Это предотвращает обход ограничений через прямой вызов application API.

## 18.3. Активное членство

Для авторизации учитываются только строки budget_members, у которых:

    revoked_at IS NULL

Пользователь без активной membership получает typed AuthorizationError.notMember.

Отсутствующая локальная пользовательская сессия возвращает
AuthorizationError.unauthenticated.

## 18.4. Автор операции

CreateTransaction и CreateTransfer дополнительно проверяют, что переданный authorId
совпадает с userId активной membership.

Создать локальную операцию от имени другого участника нельзя.

## 18.5. Управление ролями

Только OWNER может изменять роли участников.

При понижении OWNER приложение сначала считает количество активных владельцев.
Последнего активного OWNER понизить нельзя:

    AuthorizationError.lastOwner

Это правило защищает бюджет от состояния без владельца.

## 18.6. UI

Настройки содержат вкладки:

- Счета;
- Категории;
- Участники.

Для VIEWER:

- счета и категории отображаются без кнопок изменения;
- журнал транзакций остается доступен без create/edit/delete;
- план доступен только для чтения;
- роли участников отображаются без dropdown управления;
- отчеты и экспорт остаются доступны.

EDITOR получает mutation UI, но не управление ролями.

## 18.7. Public application API

AppServices предоставляет:

- canPerformBudgetAction;
- watchBudgetMembers;
- updateMemberRole.

Эти методы не заменяют guard внутри mutation use case.

## 18.8. Тесты

Покрываются:

- матрица OWNER / EDITOR / VIEWER;
- typed error для пользователя вне бюджета;
- запрет понижения последнего OWNER;
- разрешение понижения при наличии второго OWNER;
- Drift mapping ролей;
- реактивное изменение роли;
- UI управления ролями для OWNER;
- read-only UI ролей для VIEWER.
