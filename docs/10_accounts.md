# 10. Счета и текущий остаток

## 10.1. Роль счета

Счет — это источник или место хранения денег внутри конкретного бюджета.

Примеры пользовательских названий:

- Наличные;
- Карта;
- Банк;
- Накопления.

На уровне схемы тип счета отдельно не хранится: пользователь задает произвольное имя.

## 10.2. Хранение

Таблица `accounts` уже содержит:

- `id`;
- `budget_id`;
- `name`;
- `opening_balance_minor`;
- `currency`;
- `is_archived`.

Все суммы хранятся в **minor units** как `BigInt/int64`.

Начальный остаток может быть отрицательным, например для долга или кредитного счета.

## 10.3. Application API

Для счетов используются:

- `WatchBudgetAccounts`;
- `CreateAccount`;
- `UpdateAccount`;
- `ArchiveAccount`;
- `GetAccountBalance`;
- `RequireAccountInBudget`.

UI и будущие transaction use cases не должны обращаться к Account DAO напрямую.

## 10.4. Принадлежность бюджету

Все операции над существующим счетом используют пару:

```text
(budgetId, accountId)
```

Data-layer обновляет и читает счет только при совпадении обоих идентификаторов.

Для будущего создания транзакции предусмотрен guard:

```text
RequireAccountInBudget(
  budgetId,
  accountId,
)
```

Он отклоняет:

- счет другого бюджета;
- отсутствующий счет;
- архивный счет, если требуется активный счет.

Таким образом transaction flow из #10 должен вызывать этот guard до сохранения операции.

## 10.5. Текущий остаток

Баланс счета рассчитывается без отдельной materialized balance-колонки.

Формула:

```text
balance =
  opening_balance
  + income_to_account
  - expense_from_account
  - transfer_from_account
  + transfer_to_account
```

Soft-deleted transactions в расчет не входят.

Все участвующие операции дополнительно фильтруются по `budget_id`.

## 10.6. Изменение валюты

Валюту счета можно изменить, пока на счет не ссылается ни одна активная операция.

После появления операций изменение валюты блокируется.

Причина: старые `amount_minor` уже интерпретируются в валюте счета/операции. Простая смена `EUR -> USD` изменила бы смысл исторических данных без валютной конвертации.

Имя и opening balance можно редактировать независимо.

## 10.7. Архивирование

Физическое удаление счета из пользовательского CRUD не выполняется.

Архивирование:

```text
accounts.is_archived = true
```

После этого:

- счет исчезает из active account query;
- его нельзя использовать для новой операции через `RequireAccountInBudget`;
- существующие транзакции продолжают ссылаться на тот же `account_id`;
- счет остается виден в архиве;
- исторический баланс остается вычислимым.

## 10.8. Порядок

Счета возвращаются в стабильном порядке:

```text
name ASC
id ASC
```

Второй ключ обеспечивает детерминированный порядок при одинаковых названиях.

## 10.9. Ввод opening balance

Пользователь вводит обычное десятичное значение, например:

```text
1250.50
-100.00
```

Presentation/application helper переводит строку в minor units.

Текущая UI-версия использует две дробные цифры. Это ограничение только слоя ввода/отображения; в БД всегда хранится целое количество minor units.

Если позже потребуется полноценная поддержка валют с другим exponent, количество fractional digits следует получать из currency metadata, не меняя схему счетов.

## 10.10. Экран управления

В разделе «Настройки» теперь две вкладки:

1. Счета;
2. Категории.

Экран счетов позволяет:

- создать счет;
- быстро подставить название «Наличные», «Карта» или «Банк»;
- указать валюту;
- указать opening balance;
- посмотреть текущий рассчитанный остаток;
- изменить параметры;
- архивировать счет;
- увидеть архивные счета.

## 10.11. Тестирование

- запрет доступа к счету другого бюджета;
- active/all queries;
- стабильная сортировка;
- расчет income/expense/transfer balance;
- исключение soft-deleted операций;
- сохранение transaction → account после архивирования;
- widget CRUD и архивирование.
