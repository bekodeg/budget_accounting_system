# Проверка отчёта об ошибке запуска на Android

Связанные задачи: #239, #252.

Обычный запуск приложения не показывает экран ошибки. Для проверки на телефоне
используется отдельный пакет
`com.bekodeg.startuptest.budget_accounting_system`, который открывает тот же
`RuntimeBootstrapApp` и вызывает настоящий `reportStartupIssue`, но создаёт
контролируемую ошибку до открытия базы данных. Установленные бюджеты обычного
приложения при этом не изменяются.

## Сборка и проверка

1. Запустить workflow `Device Startup Reporter APK` из проверяемого commit.
2. Убедиться, что в APK указан отдельный package ID, и установить его на Android.
3. На экране ошибки сверить версию, канал `stage-device-test` и короткий commit
   с параметрами сборки.
4. Нажать «Сообщить об ошибке», затем вернуться из браузера в тестовое
   приложение, если браузер открылся.
5. Нажать «Проверить буфер». `Точное совпадение: true` означает, что Android
   вернул в буфере ровно тот URL, который подготовил обработчик отчёта.
6. Проверить «Показать ссылку issue»: ссылка должна быть доступна для выделения
   даже при отказе браузера или буфера обмена.

Не прикладывать полный URL, QR, личные данные или содержимое буфера к публичной
задаче. Достаточно зафиксировать булево совпадение, версию Android, commit
сборки и факт открытия браузера.

Эта APK проверяет реальный Android clipboard, URL launcher и экран ошибки при
отдельном пакете. Выпускная подписанная APK и конкретный естественный сбой
запуска проверяются отдельно; результат тестового пакета не заменяет их.
