# Шифрование локальной базы данных

## Решение

Нативные сборки используют SQLite3MultipleCiphers через build hook пакета `sqlite3`.
Drift открывает базу с `PRAGMA key` до любых SQL-запросов. Ключ базы данных
генерируется отдельно от identity-ключей и хранится только в platform secure storage.

## Ключ

- 32 случайных байта кодируются в base64url.
- Ключ хранится под версионированным secure-storage key.
- Ключ не записывается в preferences, Drift или application logs.
- Если зашифрованная БД существует, а ключ утрачен, приложение не генерирует
  новый ключ поверх существующей БД: bootstrap завершается ошибкой
  `DatabaseKeyMissingException`.

Потеря ключа означает невозможность расшифровать локальную БД. Восстановление
должно выполняться из отдельного зашифрованного backup, реализуемого в S5 #32.

## Миграция существующей plaintext-БД

До открытия Drift bootstrap проверяет первые 16 байт файла. Если это обычный
SQLite header, выполняется одноразовая миграция:

1. открыть БД SQLite3MultipleCiphers без ключа;
2. переключить journal mode в DELETE, чтобы корректно завершить plaintext WAL;
3. выполнить `PRAGMA rekey` с новым/существующим secure-storage ключом;
4. проверить доступ к schema;
5. закрыть соединение;
6. открыть БД через Drift с `PRAGMA key`.

При сбое миграции новый ключ удаляется из secure storage, если он был создан
именно этой попыткой.

## WAL и Drift migrations

После установки ключа применяется существующий Drift `beforeOpen`, который
включает foreign keys и WAL. Schema version и механизм Drift migrations не
меняются.

## Проверки

Integration tests покрывают:

- plaintext -> encrypted migration с сохранением данных;
- невозможность чтения зашифрованного файла без ключа;
- повторное открытие с корректным ключом;
- отказ при утрате secure-storage ключа;
- генерацию ключа для новой установки.
