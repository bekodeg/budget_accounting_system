# 1. Требования

## 1.1. Функциональные требования

| ID | Требование |
|---|---|
| FR-01 | Создание, изменение и удаление транзакции |
| FR-02 | Учет доходов и расходов |
| FR-03 | Несколько пользователей могут редактировать один бюджет |
| FR-04 | Планирование суммы по категории на месяц |
| FR-05 | Отчет за месяц |
| FR-06 | Отчет за год |
| FR-07 | Отчет за произвольный период |
| FR-08 | Расчет остатка по источнику/счету |
| FR-09 | Расчет остатка плана по категории: план − факт |
| FR-10 | Экспорт отчета в CSV |

| FR-12 | Создание транзакции из QR-кода фискального документа |

| FR-14 | Работа с данными без подключения к сети |

| FR-16 | Аудит автора и истории изменения записи |

## 1.2. Нефункциональные требования

| ID | Требование | Проектное решение |
|---|---|---|
| NFR-01 | До 20 одновременно работающих пользователей | P2P-синхронизация со временным координатором сессии вместо полного mesh |
| NFR-02 | Работа без сети | локальная БД, все CRUD и отчеты выполняются на устройстве |
| NFR-03 | Отсутствие сервера | нет постоянно развернутого backend; устройства синхронизируются напрямую |
| NFR-04 | Консистентность | eventual consistency + детерминированное разрешение конфликтов |
| NFR-05 | Сохранность | транзакционные записи SQLite, журнал операций, резервный экспорт |
| NFR-06 | Безопасность | локальное шифрование БД, ключи пользователя, подпись операций |

## 1.3. Уточнение противоречия требований

Одновременная совместная работа и полное отсутствие сети одновременно недостижимы: двум устройствам нужен хотя бы локальный канал связи для обмена изменениями.

Поддерживаются два режима:

1. **Offline isolated** — каждый пользователь работает автономно, синхронизация откладывается.
2. **Offline LAN/P2P** — интернет не нужен, но устройства соединены через локальную сеть/точку доступа и синхронизируются напрямую.

## 1.4. Дополнительные сущности, необходимые архитектуре

Исходного набора `Transaction`, `User`, `Plan` недостаточно. Добавляются:

- `Budget` — совместно редактируемый бюджет;
- `BudgetMember` — участие пользователя в бюджете и роль;
- `Category` — справочник категорий;
- `Account` — источник денег/счет/кошелек;
- `SyncOperation` — операция для синхронизации;
- `Receipt` — исходные данные фискального документа;
- `Device` — устройство пользователя для идентификации источника изменений.
